Install, run, and use the system

User Manual

Everything needed to install and operate the Clinical Lab Analysis System: requirements, installation, the inputs each question expects, operation steps, and the outputs you get back. The same manual is included as Section 6 of the final report (PDF).

1. System requirements and dependencies

  • Python 3.10 or later (developed and tested on Python 3.13).
  • The uv package manager (docs.astral.sh/uv, external link), used to install and pin all dependencies from pyproject.toml / uv.lock.
  • Core dependencies (installed automatically by uv sync): pandas ≥ 2.2, streamlit ≥ 1.36, httpx ≥ 0.27, python-dotenv ≥ 1.0.
  • Development-only dependencies: pytest, pytest-cov, playwright.
  • Optional: an API key for Anthropic, OpenAI, or Google Gemini — only if the optional large-language-model (LLM) assisted routing or the Advanced "AI writes code" mode is desired. The system is fully functional with no key at all.
  • Optional .env file: a local configuration file that links the app to the selected LLM provider by storing one key such as ANTHROPIC_API_KEY, OPENAI_API_KEY, or GEMINI_API_KEY. It enables the optional AI features, but it is not needed for the 12 predefined questions and should not be committed to Git.
  • The cleaned dataset cleaned_merged_dataset.csv (~130 MB) — downloaded automatically on first run, or placed manually in the project root next to app.py (a manual copy can be fetched from Google Drive, external link).

2. Installation and running the system

  1. Install uv, then from the project root run: 
    uv sync
    This creates a local virtual environment and installs every pinned dependency.
  2. (Optional) Copy .env.example to .env and fill in one provider API key to enable LLM-assisted routing and the Advanced code-generation mode. The app reads this file locally with python-dotenv; without it, the system runs in fully rule-based, deterministic mode.
  3. Ensure cleaned_merged_dataset.csv is present in the project root — or simply start the app and let it download the file automatically on first launch. (It can also be downloaded manually from the shared Google Drive link and placed next to app.py.)
  4. Launch the interactive UI: 
    uv run streamlit run app.py
    then open the printed local URL (typically http://localhost:8501).
  5. Alternatively, run a single question end-to-end from the command line: 
    uv run python main_pipeline.py
  6. Run the automated test suite (170 tests, with a coverage report): 
    uv run pytest

4. Operation steps

Automatic, on startup

  • The dataset is loaded once (data_prep.py) and, if missing, downloaded from the configured source.
  • The registry-driven function context used by the code generator and executor is built from questions.py.

Manual, per query

  1. From the Welcome screen, choose the Doctor or Researcher workspace (or use the direct question dropdown).
  2. Pick a category and a question (a short help caption under the selector explains the chosen question), or expand "Ask a clinical lab question in natural language" and type one.
  3. Fill in the parameter widgets that appear for the chosen question — only the parameters that question needs are shown.
  4. (Optional) Choose an interpretation mode for natural-language input (Rules only / Rules, then AI / Advanced: AI writes code), or tick the "inject a typo" demo checkbox (available for questions 1–5) to see the correction loop fire.
  5. Click Run Analysis (or Interpret & Run for the natural-language box).

If neither the rules nor the AI-assisted router can match a typed question (and an API key is configured), a popup offers to re-run it in the Advanced "AI writes code" mode — or cancel — so you are never left at a dead end.

5. Outputs

  • A color-coded status line (green = passed, blue = no matching records, red = failed).
  • Summary metric cards appropriate to the question (e.g. latest value, first-vs-last difference, count/min/max/mean, abnormal counts).
  • A trend line chart for time-series questions (trend and date-range questions).
  • Final Result tab: the result table, with a "Download Result as CSV" button.
  • Validation Audit tab: which structural and clinical rules were checked, and whether they passed.
  • Correction Attempts tab: every attempt's code, execution outcome, and validation outcome ("No correction attempts were needed" in the normal case).
  • Generated Code tab: the exact Python snippet that was executed to produce the result. (In Advanced mode the tabs are: Final Result / AI Process / Generated Code / Attempts.)
